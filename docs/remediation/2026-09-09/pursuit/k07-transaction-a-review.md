# K07 TEST_ONLY multi-record transaction composition

The account-capacity repository previously persisted a tentative reservation alone. TransactionARepositoryV31 now owns one transaction that locks the account, validates the stored latest candidate through the existing path, updates capacity and writes campaign, parent-leg, signal-preview and outbox rows. Receipt construction occurs after the transaction context exits, including on the duplicate path. No runtime service entrypoint or database connection is selected automatically.

TransactionARequestV31 binds UUID reservation/campaign/leg/signal/outbox identities, exact candidate-revision receipt, sizing request, expected initial capacity version and expiry. Campaign identity must match sizing; legacy plan/campaign labels cannot be relabeled into this contract. TransactionABundleV31 verifies immutable reservation scope, request/envelope hashes, clocks, successful sizing and initially held state. Fixed price and exact volume data derive from that verified bundle, not independent caller-supplied output fields.

Campaign, parent-leg, signal-preview and outbox rows are distinct tables with reservation uniqueness and chained foreign keys. The campaign also references the candidate revision and account ledger. Owner-token insert guards and unconditional update/delete rejection keep these TEST_ONLY records immutable. The owned transaction is responsible for creating all four records; the schema alone does not require every child row to exist if a privileged writer bypasses this repository. Replay therefore verifies completeness, IDs/linkage/account metadata, payload hashes and exact expected payloads. Current reservation immutable fields must match the recorded bundle while lifecycle state/changed clock/release receipt may legitimately have advanced. A partial bundle, corrupt capacity binding or orphan capacity is rejected rather than reconstructed.

The existing V1 FinalSignal requires a different identity/policy contract and cannot be used as a substitute for selected v3.1 authority. This slice stores wolf15.test-only.signal-preview.v31 with final_direction=WAIT, is_final_signal=false and valid_for_execution=false. It is rejected by the existing final-signal validator. The outbox is NON_DELIVERABLE_TEST_ONLY, separate from operational outboxes, and no publisher scans it. Both capital and execution authority remain false. This is source work toward atomic composition, not completion of the authority-bearing SSOT Transaction A. Active policy, strategy/risk proof and the authorized signal contract remain required.
