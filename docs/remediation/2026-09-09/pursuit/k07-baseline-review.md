# K07 baseline refresh and next-campaign budget evidence

The capacity ledger previously bound only snapshot ID and declared policy hash. It could not refresh balance/external exposure through an explicit evidence bridge. This slice binds full snapshot and full policy content plus closed balance, and adds a versioned baseline-refresh proposal. Old unbound TEST_ONLY ledger payloads fail validation instead of acquiring invented hashes; only the local fixture bootstrap currently constructs this ledger. No production migration or existing V1 repository changed.

Refresh requires a new snapshot ID, matching account/executor/USD currency and unchanged full risk policy, exact predecessor-ledger hash, continuous coverage from the previous baseline to the new snapshot, and fresh evidence relative to both account/risk-state age limits. The balance equation uses exact rational arithmetic: previous closed balance plus realized net PnL, net cashflow and broker adjustment equals the new balance. All components are explicit. Deposits are classified as cashflow, not disguised as trading profit; active capital-basis policy is still unbound. Equity/floating consistency is checked without treating floating profit as closed balance.

The external exposure baseline must exclude exactly the live reservations retained by this ledger. Set ordering does not change refresh fingerprint. A required verifier receives the complete packet; any snapshot mutation during verification is rejected. The callback and receipt hash alone do not establish independent broker truth, accurate membership or classified cashflows. Runtime provider/attestor binding and receipt retention remain necessary.

Successful refresh increments ledger version and preserves every prior reservation, including original budget and terminal tombstones. It records operation identity, predecessor/new snapshot IDs, request hash and applied version/time. Identical replay returns the current ledger, even after a newer refresh, without rolling balance back. Conflicting replay, reused snapshot IDs and retired owner epochs are rejected. A lower balance is accepted as an observation even if it makes the account over capacity; old exposure is not erased, and subsequent sizing is vetoed. A trading-disabled snapshot is likewise recordable while new sizing fails.
