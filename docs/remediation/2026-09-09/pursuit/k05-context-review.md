# K05 material context receipt bound to candidate handoff

The selected SSOT v3.1 section 12 requires material context to include counter-pressure policy and material pressure-contract status. The operational V1 material hash lacks those fields, and the existing TEST_ONLY v3.1 candidate handoff previously supplied only a context receipt hash. It could not independently check the receipt body, candidate scope or context deadline.

MaterialContextV31 now carries bounded, sorted, unique D1/H4 source identities, D1/H4 structure, price location, liquidity state, direction-domain outputs, counter-pressure policy/observation/thesis status, routes, target-map/invalidation versions and pressure-contract status. Conflicting route sets, direction-domain outputs, duplicate/cross-timeframe source IDs and missing source coverage are rejected structurally. Material hashing excludes receipt clocks and rejects telemetry/box/deployment fields. A hash is not proof of source authenticity or an allocator of epoch identity.

ContextRouteReceiptV31 binds that material body/hash to UUID context/lifecycle identities, symbol, state, explicit registry and location-policy references, route/direction, resolution receipt and aware UTC clocks. CandidateHandoffV31 requires the embedded receipt and checks its full hash, matching epoch/lifecycle/symbol/direction, ACTIVE state, allowed direction/route and validity covering both candidate decision and handoff deadline. These checks execute during revalidation before the risk verifier. The actual policy implementation must still justify the location/route decision; no universal premium/discount rule or active risk number is introduced.

The TEST_ONLY handoff discriminator is explicitly S3_S5_HANDOFF_TEST_V2. Opaque V1 receipts and missing-body forms are rejected rather than automatically relabeled. Any persisted TEST_ONLY V1 candidate rows require an explicit compatibility or re-evaluation decision before operational adoption; no database conversion occurred. Operational V1 context/thesis code is unchanged. This is a mandatory input binding on the existing TEST_ONLY path, not completion of S3/S4 runtime strategy or a broker-authorized signal.

Final run k05-ctx-0909-a2 passed 128 local tests without failures/errors/skips: 25 new context/binding cases and 103 existing handoff/revision/latest-candidate/capacity/transaction cases. Exact JUnit identities and unchanged source were verified. a1 had 117 passes and two failures when the new scope validation intercepted older immutable-plan fixtures earlier; those fixtures now rebind internally coherent context before testing plan immutability. Both receipts are retained. Ruff, formatting and diff checks pass. No PostgreSQL suite was run or represented as passing; inventory IDs and historical source bindings are preserved.

Serial review checked context scope, UTC normalization, material-versus-receipt identity, bounded collections and fail-closed compatibility.
