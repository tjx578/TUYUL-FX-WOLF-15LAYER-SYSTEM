# Replay retention through the reconciliation caller

The caller previously returned a sealed report while discarding raw inputs required for replay. An explicitly supplied synchronous sink now receives a portable typed bundle and a separately retainable receipt digest. It must return literal True after durable acceptance; errors, missing acknowledgements and accidentally asynchronous sinks prevent report return. Default CLI behavior does not configure a sink or persist raw evidence.

The codec preserves datetime, Decimal and UUID, including literal dictionaries resembling type tags. It uses JSON data only, rejects duplicate keys and noncanonical/type-invalid payloads, and bounds decoded input at 8 MiB and nesting at 64. This is an engineering resource guard, not a trading policy. The codec is included in local orchestrator source binding. It provides no encryption or collector attestation. A selected confidential storage backend, independent digest custody and durability verification are still required before operational use; arbitrary caller callbacks are not a trusted-storage guarantee.
