# K07: explicit v3.1 geometry to parent sizing

The current reservation repository still consumes Strategy5SCRTradePlan V1. Target/net geometry v3.1 is TEST_ONLY. This slice implements the typed policy/account/spec portion of AC-K07 without renaming v3.1 or shadow candidate IDs into the legacy reservation schema. No active policy or account is selected. The existing V1 reservation path and production service entrypoints remain unchanged.

ParentSizingRequestV31 requires semantic plan/revision/thesis/campaign IDs, the expected account/executor, snapshot, broker mapping, tick-value denomination/model, explicit risk policy, geometry, and fresh capacity-state evidence including held reservations. All risk numbers and tolerances are mandatory. The full request is hashed and passed to a required verifier; a nested snapshot changed during verification is rejected. The hash is provenance binding and is not strategy identity or authentication. A permissive callback cannot establish real authority.

The adapter reruns the existing fixed-target net geometry kernel, then calculates exact rational USD profit/loss using the explicitly bound per-lot tick model. It includes each spread, commission, slippage and swap loss cost once. Profit and loss tick values can differ: a price-feasible candidate fails if its monetary net RR is insufficient. It rejects that selected entry rather than moving the target or changing strategy geometry. It floors volume to the broker step, rejects out-of-range lots under the explicit test policy, checks the exact account cap, and calculates the parent budget from closed balance. Floating profit does not enlarge it. Existing campaign exposure blocks this parent sizing path; this is not a duplicate-reservation handler or child evaluator.

Money and volume outputs use numerator/denominator pairs to avoid rounding or Decimal context dependence. The output is SIZED_TEST_ONLY, with no capital reservation or execution authority. The budget is calculated, not durably locked. Tick values use the precision supplied by the existing float-based account snapshot; this does not recover unavailable broker precision. Margin/free-margin, full admission/thesis authorization, runtime cost/provider attestation, persistent capacity reduction, conflict recovery, and command issuance remain downstream gates.
