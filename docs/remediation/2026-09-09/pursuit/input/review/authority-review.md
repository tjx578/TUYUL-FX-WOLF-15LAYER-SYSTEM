# Review kontrak pursuit dan batas authority

## Tujuan Prompt

Memberi Codex Desktop Definition of Goal, tindakan P1–P6, dependency dan respons blocker yang operasional. Artefak ini mengatur pursuit berdasarkan source dan scope; tidak menjalankan repository atau broker.

## Kekuatan

41 canonical actions dipertahankan. G00 dan 12 local slices membantu progress engineering selama external gate terblokir. Launch instruction membedakan adopsi mandat implementasi dari scope produksi/DEMO. Pertanyaan dan jawaban existing direuse; trigger retry harus mempunyai perubahan kondisi.

## Celah / Ambiguitas

Source HEAD terbaru, runtime Linux/PostgreSQL, current CI, policy aktif, transport/consumer dan binding DEMO belum diverifikasi langsung pada penyusunan paket. Latest checkpoint diberi USER_REPORTED. Salinan SSOT historis bukan pengganti selected repo bytes. Durasi, biaya, peluang kegagalan dan kebutuhan resource belum diukur. Rencana PARTIAL_PLAN mempunyai external preconditions yang jelas; itu berbeda dari kekurangan langkah perencanaan.

## Risiko Authority Drift

Risiko utama adalah menganggap PASS struktur rencana sebagai PASS sistem, projection/advisory sebagai source executable, lease relay sebagai fencing lifecycle, bool executor sebagai independent broker proof, dan parent-only sebagai goal family. L1–L11 analysis, source-bound L12 verdict, separate capital-risk, EA mechanical execution dan journal record-only harus dipetakan ke source aktual. Relasi V11/L12 tidak diinventarisasi sebagai runtime terverifikasi. Nomenklatur layer mengikuti SSOT/source terpilih jika dokumen historis berbeda.

## Perbaikan Disarankan

G00 melakukan rebinding. Status evidence, stage implementasi dan closure dipisahkan. External input dicari dulu dan dikelompokkan dalam cohort yang sedang siap. Semua unknown policy tetap null/UNBOUND; template bukan approval. Scope otorisasi yang masih sah tidak diminta ulang. Review REAL dapat selesai dengan verdict HOLD bila evidence cukup; mandatory technical defect tetap menghambat gate terkait.

## Catatan Implementasi

Tidak ada modifikasi README, repository, CI, Railway, database atau broker dalam pekerjaan ini. Hash manifest dan validators membuktikan integritas/struktur yang diuji, bukan availability atau profitability. Pemeriksaan domain dilakukan oleh dua agent pada dokumen yang tersedia; hal itu tidak menutup review independen source PR terbaru. Receipt studi negatif harus tetap dibedakan dari positive evidence. Scope single-owner transaksional tidak dengan sendirinya mencegah broker side effect EA lama; handoff submission memerlukan bound executor/session dan reconciliation.
