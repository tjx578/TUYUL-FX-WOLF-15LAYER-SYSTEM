# Bounded S01 pressure-authority correction

Implemented only two new repository files: contracts/strategy_5scr_pressure_authority_v31.py and tests/test_pressure_authority_v31.py. No legacy consumer, candidate model, lifecycle enum, migration, provider, or Git state was modified by this implementation.

G01: the new producer authority snapshot explicitly requires pressure_contract_version and an explicit nullable pressure_contract_invalidated_at, as required by selected SSOT section 10.5. Both enter the deterministic evidence hash together with the entire source snapshot, caller policy evidence and decision timestamp. Naive timestamps, inconsistent lineage, inferred LOCKED state, missing formal transition provenance, invalid source IDs and extra legacy fields are rejected. Present/future invalidation and future/expired observations cannot pass the gate.

G04: a pure pressure-direction prerequisite table permits only aligned, current BUY/SELL evidence with an explicit current APPROVED policy binding. Radar does not infer a locked direction. Consolidated mode requires explicit LOCKED source-bound formal transition and agreement between requested direction, locked direction and current pressure consensus. Conflict, unavailable lineage, stale/incomplete consensus, unresolved/open consolidated status, absent/unbound/revoked/future/expired policy all deny. The independent separate-route gate always remains false because its permissive conflict policy is unresolved. All hypothesis, risk and execution authority flags are Literal[False]. A successful pressure-direction prerequisite is not a hypothesis creation grant: all selected section 10.2 analysis-admission, maturity, lifecycle and source prerequisites still belong to consumers.

G08: exported three schemas directly from Pydantic 2.9.2 models. Five valid examples include both allowed prerequisite and valid denied snapshots; five invalid examples are rejected by model validation. Draft2020-12 meta-schema validation passes for all three schemas and all fifteen valid authority/policy/decision objects pass JSON Schema validation. Cross-field lineage/LOCKED rules are enforced by Pydantic model validators; JSON Schema alone cannot enforce those semantics. The validation receipt explicitly distinguishes structural schema rejection from semantic model rejection.

Verification: 96 tests passed, zero failures/errors/skips under Python 3.11.9 / Pydantic 2.9.2, with JUnit in pressure-authority-v31-tests.xml. Includes 60 mode/alignment/consensus/requested-direction table cases, policy binding failures, timestamp boundaries, contradictory locked/current directions, required field presence, extra/authority-field rejection, instance-copy bypass validation, version/invalidation hashing, and example roundtrip. Ruff lint and format both pass. Tests used --noconftest and no pytest cache; they are pure local contract tests, not runtime or PostgreSQL proof.

Remaining limitations: policy approval is explicit caller-supplied data, not authenticated by this module; no actual production policy identity was invented or activated. This new gate is not integrated with hypothesis/L12/risk/execution consumers. Separate-route permissive policy, full v3.1 lifecycle/candidate/schema consistency, active policy registry and mandatory post-verdict wiring remain open. G01/G04/G08 are locally improved within this new contract only; full S01 DONE remains false. Parent must independently review and integrate the code and include its final combined test evidence.
