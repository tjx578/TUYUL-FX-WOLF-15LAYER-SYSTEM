# SignalJSON Structure-Aware Counter-Entry Contract

## Scope

This contract applies to `MICROBOOST_COUNTER_ENTRY` results produced from a
priced microboost warning at key structure. It separates analysis validity from
immediate execution readiness. The `TP1 >= 2.0R` execution invariant applies
to all final SignalJSON families, including trend-continuation and
breakout/breakdown continuation events.

## Repository Assessment

Before schema version `1.1-structure-aware`, the counter-entry path already
detected resistance/support rejection and exported several flat structure
fields. It had four execution weaknesses:

1. RR validation used `sl_tight` while a safer `sl_safe` value was available.
2. `tp1..tp4` were treated uniformly, so a nearby low-RR support could appear
   as the first executable profit target.
3. The pipeline extended an observed ladder into synthetic levels to fill four
   target slots.
4. Finality gates accepted `valid_for_execution=true` without requiring
   numerical invalidation, risk, zones, or selected targets.

## Target And Stop Policy

For counter-entry signals:

- `selected_sl_mode` defaults to `SAFE` when `sl_safe` is available.
- `risk_pips`, `selected_risk_pips`, and RR validation use `selected_sl`.
- `TP1` is mandatory and calculated at `SIGNAL_JSON_TP1_RR_REQUIRED`,
  default `2.0R`; configuration cannot reduce this execution floor below
  `2.0R`.
- `TP2+` are optional and only exported from observed M15/H1 structure levels
  beyond TP1; no extrapolated ladder levels qualify.
- A counter-entry final execution still requires an observed structure target
  reaching `SIGNAL_JSON_MIN_RR_VALID`, default `2.5R`.
- A structure target too close to TP1 is suppressed when separated by less
  than `0.20` of initial risk.

This preserves the existing executor configuration `TP1_ONLY` while exporting
auditable extension targets for management and dashboards.

For final continuation decisions, the exporter also canonicalizes TP1 to fixed
`2.0R`. Nearby observed structure remains useful as reclaim context, but is
not exported as executable TP1 when its reward is below the floor. A source
direction that does not pass the strict export gate is recorded as
`SignalDecisionUpdateJSON`, with its analytical status and direction retained
as source metadata.

## Breakout Resolution Of A Counter-Entry Watch

A breakout or breakdown that invalidates a `MICROBOOST_COUNTER_ENTRY` watch
continues to use the existing analytical decision status, for example
`BUY_BREAKOUT_CONTINUATION_VALID`. Enrichment does not alter that internal
status, direction, action, M15 confirmation, or the Layer 12 verdict. When a
complete structure-aware tradeplan cannot be built, output is downgraded to
`SignalDecisionUpdateJSON` and adds:

- `direction_valid=true`
- `analysis_valid=true`
- `tradeplan_valid=false`
- `execution_valid_now=false`
- `valid_for_execution=false`
- `execution_status=BLOCKED_SIGNAL_JSON_STRICT_GATE`
- `source_status=<analytical final status>`
- `source_final_direction=<analytical final direction>`

A provisional RR ladder remains source evidence only. It cannot authorize
execution or appear as final execution-grade `SignalJSON`.

## Non-Mutating Output Enrichment

`analysis.signal_json_enrichment` is applied only while constructing exported
SignalJSON data. It works on a copied payload and never changes the source
classification or lifecycle state.

For a bullish resistance breakout such as the supplied GBPCAD fixture:

1. The analytical result remains `BUY_BREAKOUT_CONTINUATION_VALID` and
   `final_direction=BUY` when generated by the existing M15 decision path.
2. The exported tradeplan selects the structure-buffered safe stop when available and
   computes mandatory TP1 from that selected stop at `2.0R`.
3. TP2 and later targets are exported only from observed ladder levels beyond
   TP1; no pair-specific price is hardcoded into strategy logic.
4. `valid_for_execution=true` in output is retained only when coherent phase,
   normal spread, a non-expired signal, and the complete structure-aware
   execution contract are present.

The SELL breakdown path is symmetrical. This separates a final analysis
direction from an executable tradeplan without changing signal-generation
behavior.

## Strict Lifecycle Export Gate

The default export policy is conservative:

- Every final `SignalJSON` references an emitted parent watch through
  `parent_watch_id`, or uses an explicitly enabled `DIRECT_BYPASS` path with
  a stated `bypass_reason`.
- `PROVISIONAL_RR_FALLBACK` remains decision/watch evidence and is not
  execution-grade by default.
- A theme conflict downgrades a final candidate unless a second M15
  confirmation is explicitly supplied.
- A candidate opposing an active signal requires explicit reversal
  confirmation and at least one M15 cooldown bar before final export.
- A pending decision that has finalized or expired is terminal for subsequent
  decision-update output.

These rules run in finalizer, lifecycle, and emitter/export handling. Layer 12
market analysis remains present as source metadata and is not rewritten by the
export gate.

## Final Execution Gate

`execution_valid_now=true` is allowed only when all of the following are true:

- A relevant rejection/support zone, `key_resistance`, and `key_support` exist.
- Entry zone, selected SL, selected risk, hard invalidation, and canonical
  targets are present.
- An observed structure target reaches the configured final RR threshold.
- M15 rejection/direct absorption confirmation has been obtained.
- Spread is available and accepted by the existing market-context spread gate.
- H1 is not explicitly directional against the counter-entry.

The output enrichment adapter enforces the TP1 invariant and execution
metadata contract for emitted JSON. A source decision that fails the
execution-grade contract remains auditable in a decision update, but cannot
appear as final merely by setting `valid_for_execution=true`.

## Exported Objects

The event schema exports:

- `target_policy` and `targets`
- `structure_zones`
- `risk_reward`
- `invalidation_rules`
- `execution_quality`
- `phase_coherence`
- `signal_expiry`
- `analysis_valid`, `tradeplan_valid`, `execution_valid_now`, and
  `execution_status`
- `parent_watch_id`, `promotion_path`, `execution_grade`, `audit_valid`, and
  `audit_block_reasons`

## Available And Unavailable Evidence

The current live pipeline can derive M15/H1 (and record H4 when present),
observed support/resistance ladders, tick spread, and configured normal spread
limits. It does not yet supply authoritative currency-strength ranks, scored
historical touch/freshness metadata, volume/POC levels, or a calibrated
multi-timeframe coherence score. Those fields must not be populated with
guessed values; they require a separate data-source and scoring implementation.

## AUDNZD Audit Fixture

The regression fixture for AUDNZD uses the submitted levels as an input
scenario, not as a claim about a currently verified live quote. With entry
`1.22158`, safe SL `1.22375`, and pip size `0.0001`, the contract calculates:

- selected risk: `21.7` pips
- mandatory TP1 at 2R: `1.21724`
- observed structure extensions: `1.21562`, `1.21492`

When the fixture reports a `4.0` pip spread above its accepted spread gate, the
analysis and tradeplan remain valid but the output is
`WAIT_SPREAD_NORMALIZATION`, not a final execution signal.
